## Coordinator sessions delegate execution and expensive tests

Interactive user-facing coordinator sessions (`ida` / `Sub-Ida`) and main conversational contexts exist to triage user requests, capture and consolidate repository-scoped tasks on the graph via `/q`, curate knowledge, delegate work via `/dispatch`, and verify returned handback arguments. Pre-dispatch task reification is removed from interactive coordinator duties. Interactive coordinators do not execute heavy labour in-session.

- **Prohibition on expensive tests in-session**: Coordinator and interactive agents are strictly prohibited from running expensive test suites (such as `uv run pytest`, `make test`, or integration tests) or build pipelines directly in-session. All test suite execution and runtime builds must be delegated to isolated execution containers (`polecats`).
- **Prohibition on sweeping codebase greps and scans**: Coordinator agents must not perform sweeping repository searches, large codebase greps, or full-file inspection chains across the repository in-session. Targeted read-only inspection of repository markdown files (such as workflow templates in `.agents/templates/`, specifications in `specs/`, and project rules) and single-file lookups needed for planning, review, or in-turn answers are permitted. When deep code investigation, refactoring analysis, or codebase exploration is required, the coordinator must dispatch an isolated probe or worker task to a polecat.
- **Delegation boundary**: Substantial implementation, code modification, runtime verification, repository search sweeps, and test execution tasks must be queued and dispatched to isolated execution containers (`polecats`) via `/dispatch`. Isolated polecat containers running `/supervise` (for repository-scoped epic tasks assembling workflows via `/reify` and coordinating subagent fan-out) or `/pull` (for fast-path leaf execution of pre-composed tasks) are the execution surface authorized to fan out implementation, builds, repository searches, and test suites. In-session work in interactive coordinator sessions is confined to in-turn conversational answers, PKB graph operations (intake and capture via `/q`), worker dispatch (`/dispatch`), and checking returned handback arguments per `premise-check`.
