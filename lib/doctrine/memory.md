## Durable Capture

Write facts, decisions, and state to the knowledge base the moment they emerge; do not wait to be asked. The mechanics live in the `remember` skill — do not re-derive them.

- **Capture knowledge, never verdicts.** What was learned — a build prerequisite, a constraint, the cause of a flaky test — not the pass or fail of the review that surfaced it.
- **Update, don't duplicate.** Check whether a document exists before creating one; merge into it and cite it rather than recording redundantly.
- **The knowledge base is the only persistence surface** for session and task state — never instruction files, chat files, scratch, or an agent's own charter. Machine-local host config is exempt.
- **No workarounds.** If a memory tool cannot do what you need, file the gap; never route around it.
