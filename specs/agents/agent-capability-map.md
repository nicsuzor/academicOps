# Agent Capability and Constraint Map

Factual inventory of every agent **definition** file in the repository — a file that declares an operable agent identity (frontmatter naming the agent, loaded by a harness or workflow), as distinct from a _spec about_ an agent's design. Every tools/authority/constraint claim below traces to a specific line in the cited source file; nothing here is inferred beyond what the source states. Companion to [skill-capability-map.md](skill-capability-map.md) (the skill-side half of this inventory, PR #2296).

"Authority level" is not a named enum in this framework — [agent-authority.md](agent-authority.md) defines a schema of independent axes (tools, MCP servers, bash scopes, filesystem access, skills, sub-agents) rather than tiers. Each row below reports what that agent's frontmatter actually declares on each axis, including axes it leaves **undeclared** — per the deny-by-default grid ([agent-authority.md:83-95](agent-authority.md#L83-L95)), an undeclared axis means that capability is _not_ granted, even if a related tool name appears in `tools:`. Those gaps are reported as facts about the current source, not as findings or recommendations — judging whether they're bugs is the separate audit task ([[aops-35e31b8c]]), not this inventory.

## Scope

Searched (per task body) `specs/agents/*.md`, `aops-jr/agents/*.md`, `aops/agents/*.md`, `aops-tools/agents/*.md`, and confirmed via repo-wide search for any other `*agent*.md` files:

- `aops/agents/*.md` — 4 files, all agent definitions (core, in-session).
- `aops-jr/agents/*.md` — 2 files, both agent definitions (interactive head personas).
- `.github/agents/*.agent.md` — 5 files, all agent definitions (GitHub Actions PR-pipeline agents), **not** one of the four listed globs but explicitly in scope per [agent-authority.md:23](agent-authority.md#L23) ("`aops/agents`, `.github/agents` — Must conform") and [agent-authority.md §GitHub Action Agents](agent-authority.md#L182-L184).
- `aops-tools/agents/*.md` — directory does not exist (confirmed: `aops-tools/` contains only `README.md`, `skills/`, `templates/`). Zero rows.
- `specs/agents/*.md` — 7 files (`agent-authority.md`, `agents.md`, `ida.md`, `james.md`, `marsha.md`, `pauli.md`, `rbg.md`), all `type: spec` with no `tools:` frontmatter — these are design/rationale documents _about_ the agents (schema, ecosystem overview, per-agent fitness specs), not the operable definitions the harness loads. Excluded from the row count for that reason; the operable definitions they describe live in `aops/agents/*.md` and `aops-jr/agents/*.md` and are rowed below.
- `.github/agents/shared-error-handling.md` — excluded: no frontmatter (no `name:`), a prompt fragment concatenated into other agents' prompts at workflow run time (e.g. `agent-qa.yml:181`), not itself an agent identity.

**11 agent definition files, 11 rows.**
