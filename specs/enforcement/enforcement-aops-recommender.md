# Enforcement Recommender: /aops Pattern Detection & Escalation

## Problem

The framework has a 7-step evidence loop for enforcement (`specs/enforcement.md` §5). While Steps 1–3 (capture and accumulation) and Step 6–7 (implementation and closing the loop) are implemented, Steps 4–5 (pattern detection and recommendation) remain a principal gap. Without these steps, the "Severity Pyramid" lacks a mechanical signal for when to escalate or de-escalate rules.

## Design Answers

### 1. Inputs: What feeds the loop?

The primary source is **GitHub Issues** in the framework repository.

- **Filter**: Issues with labels `bug`, `framework`, `enforcement`, or `axiom`.
- **Priority**: Issues with `criticality:high` or `criticality:critical`.
- **Structure**: The **Root Cause Analysis (RCA)** YAML block generated by `/learn` is the high-signal target. Specifically:
  - `Root cause category`: (Detection Failure, Enforcement Gap, etc.)
  - `Framework layer that failed`: (Which component/hook)
  - `Expected vs Actual`: (The behavioral gap)
- **Secondary**: Session summaries (`$AOPS_SESSIONS/summaries/*.json`) provide high-level context but are lower-signal than structured `/learn` issues.

### 2. Pattern detection shape: What counts as a pattern?

Pattern detection uses **Semantic Clustering** on the `Failure` and `Root cause` fields of the RCA block.

- **Signaling Thresholds**:
  - **Volume**: 3+ occurrences of the same (axiom, component) pair within 14 days.
  - **Severity**: Any `criticality:critical` issue that identifies an `Enforcement Gap`.
  - **Bypass Signal**: An issue noting a violation of an axiom that already has a `warn` tier mechanism. This indicates the existing mechanism is being ignored and needs escalation to `block`.
- **Noise Filter**: Issues categorized as "Capability Failure" (agent knowledge gap) or "Index Lag" are treated as maintenance tasks, not enforcement patterns.

### 3. Recommendation output: What does /aops produce?

The `/aops` command (or sleep cycle phase) produces:

1. **Briefing Note**: A markdown document for the human operator (stored in `data/brain/recommendations/`) summarizing the pattern and citing the source issues.
2. **Draft Enforcement Change**: A proposed `git diff` for `specs/enforcement-map.md`, escalating (or de-escalating) a specific row's tier.
3. **PKB Task**: A new P2 task in the `aops` project: "Review Enforcement Recommendation: [Pattern Slug]".
4. **Implementation Epic**: If the recommendation requires a new mechanism (not just a tier change), it drafts a follow-up epic.

### 4. Cadence: When does it fire?

- **Primary**: Part of the **`/sleep` cycle** (Phase 7: Enforcement Review). It runs every 6 hours on GitHub Actions.
- **Secondary**: Manual **`/aops`** invocation within a session for on-demand strategy review.
- **GHA Cron**: The periodic sleep cycle ensures evidence doesn't rot.

### 5. Trust model: Human-in-loop?

- **Autonomous Flagging**: Allowed. The system can identify patterns and stage recommendations without permission.
- **Human Decision (MANDATORY)**: No mechanical changes to `enforcement-map.md`, `AXIOMS.md`, or `RULES.md` are auto-merged.
- **Enforcement**: Recommendations are staged as PRs or PKB tasks. A human must review and approve the PR to close the loop (Step 6).

### 6. Existing infrastructure to reuse

- **`/sleep` orchestrator**: The existing GHA infrastructure for periodic processing.
- **`find_duplicates` tool**: Re-use for semantic clustering of issue bodies.
- **`gh` CLI**: Already configured for evidence retrieval.
- **`/learn` skill**: The mandatory RCA block is the foundation of the recommender's parser.

### 7. Integration with the linter

- **Linter (`task-7dd4c825`)**: Enforces **Structural Integrity**. It blocks PRs if pointers (A#, R#) are broken or the map is malformed.
- **Recommender (`/aops`)**: Enforces **Empirical Effectiveness**. It identifies when the _assigned_ tier is insufficient for the _observed_ failure rate.
- **Boundary**: If a rule exists but doesn't work, it's a recommender issue. If a rule's definition is missing its axiom back-pointer, it's a linter issue.

### 8. Out of scope

- Building the semantic clustering engine.
- Implementing the auto-PR generation.
- Real-time detection (PostToolUse hooks are handled by the `enforcer` agent, not the recommender).

## Worked Example: A8 Workaround Pattern

### Step 4: Pattern Detection

The recommender scans issues from the last 14 days:

1. Issue #720: "agent offers workaround menu... A8 violation" (High)
2. Issue #725: "agent bypasses tool failure with manual grep... A8 violation" (Medium)
3. Issue #729: "rbg missed workaround offer in prose... A8 violation" (High)

**Pattern Found**: Axiom A8 (Halt on Failure) is being bypassed through "Workaround Substitution". Existing mechanism `auto-mode: Silent Workaround` (Tier: `warn`) has been bypassed 3 times.

### Step 5: Recommendation Generation

- **Recommendation**: Escalate `A8 Halt` / `auto-mode: Silent Workaround` from `warn` to `block`.
- **Output**:
  - Diff for `enforcement-map.md`.
  - Briefing citing #720, #725, #729.
  - PKB Task: `aops-89b501b3-a8-escalation`.

### Step 6: Human Decision

User runs `/pull aops-89b501b3-a8-escalation`, reviews the briefing, and merges the PR.
