# Enforcement Map

The authoritative current-state register of how the framework enforces every rule and nudge.

- **Stated Purpose:** Provides an empirically verified single source of truth (SSoT) mapping each rule and nudge directly to its implementation mechanism and escalation severity index.
- **Primary Audience:** Developers, system architects, and auditors who need to verify, tune, strengthen, or remove enforcement mechanisms in the codebase.
- **Design Intent:** For architectural theory and the escalation ladder, see [`enforcement.md`](enforcement/enforcement.md).

## Columns & Vocabulary

The register is maintained as a single flat table with 4 columns:

1. **Rule / nudge** — The operative obligation, constraint, or steering affordance, formulated with logical accuracy.
2. **Mechanism** — The carrier category, drawn strictly from the 10-term controlled vocabulary:
   - `agent persona instructions` — Guiding text in an agent's persona prompt (`plugins/*/agents/*.md`).
   - `skill instructions` — Operational text in a skill's instruction file (`SKILL.md`).
   - `hook` — Handler on a runtime lifecycle event (`PreToolUse`, `PostToolBatch`, `Stop`, `SessionStart`, etc.).
   - `tool grant` — Configuration or frontmatter granting, scoping, or denying tools/models.
   - `structural check` — Hard code-level guarantee (mount permissions, fail-closed configs, native loading).
   - `workflow gate` — Checkpoint governing work progression across stages (branch protection, task contracts).
   - `CI job` — Named CI workflow posting a status check.
   - `observability` — Tracing, logging, or metrics pipeline that records without gating.
   - `doctrine` — Declared principle or spec without automated code enforcement.
   - `not enforced` — A declared rule or constraint with no active enforcement in code, hooks, tool grants, or prompts.
3. **Severity** — Index of escalation within each mechanism category:
   - _Instructions:_ `suggestion` · `advisory` · `imperative` · `absolute`
   - _Hooks:_ `warning` (advisory notification) · `block` (hard stop/withholding)
   - _Tool Grants:_ `scoped` (restricted toolset) · `denial` (explicit block)
   - _Structural Checks:_ `hard guarantee` (physical/container boundary) · `fail-closed` (unrecoverable fast-fail)
   - _Workflow Gates:_ `checkpoint` (review step) · `blocking gate` (hard barrier)
   - _CI Jobs:_ `advisory check` · `required gate`
   - _Observability:_ `trace` · `log`
   - _Doctrine:_ `declared principle` · `unbacked policy`
   - _Not Enforced:_ `none`
4. **Detail** — Concrete pinpoint reference (`path:line` + operative quote, hook event + handler function, or CI workflow + job name) and operational state flags:
   - `[DISABLED]` — Mechanism exists in code/config but is currently inactive or toggled off.
   - `[MAP DRIFT]` — Codebase reality contradicts previous register claims.
