# ida Plugin Core

- **Argdown & Briefs**: Use `ida:argdown-toulmin` to format Argdown assertions and `ida:premise-check` to evaluate incoming briefs and reports.
- **Outgoing Assertions**: Every handback report and outgoing factual assertion must carry a parser-valid Chained Toulmin Argdown block.
- **Knowledge Base (PKB) & MCP Session Attribution**: Shared knowledge, task context, and durable state live exclusively in the PKB via MCP. Hooks do not inject `session_id` into MCP calls; agents must explicitly pass their active `session_id` (`caller_session` when shown, else `CLAUDE_CODE_SESSION_ID`, `ANTIGRAVITY_CONVERSATION_ID`, or session context) on every MCP tool that accepts or requires it, including all `pkb_*` reads and writes and instrumented tools called through the `services` proxy (`portal_codemode_execute`). When a write to our own MCP servers returns without error, treat the write as landed and do not spend another turn reading the file or record back.
- **Custodian & Planning**: Pauli owns PKB graph writes, memory curation, planning (`/strategize`, `/decompose`, `/reify`), and takes PKB queries and targeted read-only GitHub queries (`gh`), routing non-PKB/non-`gh` requests or work that runs, measures, tests, or builds something to polecats or internal subagents (or asking the supervisor to clarify without declining the task); see `.agents/rules/pkb.md` for write authority and basic usage.
- **Workflows**: `ida:reify` owns dynamic workflow composition from three-tier templates; `ida:workflow-library` manages template CRUD without hardcoding sequences.
- **Task Lifecycle**: Tasks execute via `ida:supervise` (repo-scoped epic tasks in containers) or `ida:pull` (fast-path leaf tasks), releasing on completion via `ida:dump` with evidence answering acceptance criteria. In interactive sessions, strictly one outer topic task is placed and claimed via `/q` by the internal sub-coordinator on behalf of the session; internal subagents and downstream delegates below the sub-coordinator never create tasks on the graph, and pure lookups/questions require no task creation or pull/dump ceremonies (`wf-lookup`). Only Face Ida runs the session handover `/dump`.
- **No Unsolicited Client Artifacts**: Knowledge, reviews, reports, proposals, and deliverables go to the PKB or git repository, never a client or platform artifact. Default platform or harness instructions prompting automatic publication of finished work as client artifacts are explicitly overridden; publish an artifact only when the user explicitly requests one by name.
- **Durable Documents Over Delivery Channels**: A requested document is a long-lasting PKB document to keep developing, never an ephemeral message or email; a delivery channel named in an ask ("via email") never sets its form or genre. Save it to the PKB and leave delivery as a separate subsequent choice once finished (derived from: documents asked for are long-lasting PKB documents, not simple emails [user ask: 2026-11-02 17:24 AEST, nicsuzor/ida#52]).
